## 1. A defect in an already-landed header: `include/poly_text.h`

This is the item most deserving review. The header describes the buffer
`ov29_022DC33C` takes, and `src/poly_text.c` already decompiles
`ov29_022DC240` / `ov29_022DC2B8` against it — so the layout is backed by
**matching code**, which is what makes the errors surprising.

- **Fact**: `s16 unk17704[0xf92]` runs `0x17704` → `0x19628` and therefore
  **swallows the 350-element array at `0x18304`**. The split is `[0x600]`,
  ending exactly at `0x18304`, followed by a 14-byte-stride array of 350.
  Corroborated independently by the file's own landed code:
  `ov29_022DC240` sets `unk8 = 0x40` and `unka = 0x18`, and `ov29_022DC2B8`
  zeroes `unk17704[i]` for `i < unk8 * unka = 0x600`.
- **Fact**: `s16 unk19628` must be `u16`; the target loads it with `ldrh`, and
  `s16` costs 2 structural rows (measured under two different layout models).
- **Fact**: line 13 was `} unk1962a;` — a file-scope **tentative definition
  inside a header**. MWCC emits it as a *defined* symbol, not COMMON, so a
  second includer is a hard duplicate-symbol collision. That was load-bearing:
  the caller cannot drop its stale externs without including the header.
  **Deleting** the variable is *not* object-neutral (1000 → 928 bytes, `.bss`
  `0x10` → 0); **moving** it into `src/poly_text.c` is, and that is what was
  done.

`src/poly_text.c` was compiled before and after with the real build flags and
produced an identical object, so the correction is proved rather than argued.

## 2. `FindNearbyUnoccupiedTile`: the tree's return type was wrong

**Fact**: the target stores the literal `1`, and `out` is an output parameter —
the function is a predicate. The tree declared it returning `struct position *`,
and three already-landed wrappers returned its result directly.

The wrappers and `include/overlay_29_022E99F0.h` are retyped to `bool32`.
**Fact**: every call site already uses the result as a boolean
(`src/overlay_29_02320764.c:331, 338, 347, 354`), none assigns it to a pointer
or compares it to `NULL`, and `FindFarthestUnoccupiedTileWithin2` has no C
caller at all. `bool32` rather than `bool8` because the wrappers tail-return
`r0`. The three `DISPLACEMENTS_*` externs become `const struct position[]`: the
asm indexes with `lsl #2` then reads two signed halfwords four bytes apart,
which `const s32 *` cannot produce, and the rodata decodes as `{s16 x, s16 y}`.

All four affected objects compile byte-identically to their pre-landing
versions.

## 3. Two things measured inside the compiler

Both are **fact**, read from `mwccarm` build 137 under gdb, and both retired
families of source-level guesses that had already consumed dozens of attempts:

- **`restrict` is not aliasing information here.** It makes `struct T *restrict`
  a *distinct type*, so the assignment carries a conversion node, and
  `IRO_ExpressionPropagation` will not fold a copy across one. With the
  conversion the pointer holds 24 references at all 81 pass boundaries; without
  it, 24 → 1 at that pass and → 0 at dead-store elimination. **Inference
  (well-supported)**: therefore *any* genuine conversion works — which is why
  the landed form is a plain `const` pointer declared after the guard, with no
  `restrict` and no contract to violate.
- **`smlabb` requires a cast, and that is a proof, not a tally.** C pointer
  arithmetic scales by `sizeof(pointee)`; the target needs a 14-byte pointee
  *and* a `0x18304` displacement on that base, i.e. a type of at least `0x18312`
  bytes. Those cannot be one type, and `smlabb` arises only from *implicit*
  index scaling (nine explicit multiplies measured, none produce it).

## 4. A read of an uninitialised local, which is a property of the ROM

**Fact**: `ov29_022DC33C`'s target does `ldrh r3, [sp]` before anything stores
to that slot. The real build's `-W error` rejects the direct spelling, and
neither a one-member struct nor a one-element array suppresses it (both
measured). Reading and writing through a pointer local satisfies the diagnostic
and emits nothing — 130/130 words byte-identical.

**Inference**: retail's own source read an uninitialised local here. The pointer
local is a stand-in chosen to satisfy the tree's warning flags, not recovered
source, and a reviewer may prefer a different spelling.
