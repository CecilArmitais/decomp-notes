## Matching findings

**A bitfield read is not the same as the equivalent shift expression.** MWCC
folds `(x << 28) >> 28` into `and #0xF`; the target keeps both shifts. A member
declared `u32 f : 4` emits `lsl #28` / `lsr #28` exactly. This was found on
`Dwci_Entry`, which is not in this commit, but the technique is general and is
now in `docs/MATCHING_TIPS.md`.

**A shared destination forces a shared type.** G2 and G3 land in the *same file*
and both involve `GetMoveAnimation`. G3 was written first, against an invented
`struct unk_move_anim` read at `field_0x8`; G2 defines the function as returning
a `0x18`-byte element of `MOVE_ANIMATION_INFO`. Unified into one
`struct move_anim_info` and **all seven affected functions re-scored at 0**. This
class of conflict only appears once two groups share a destination file, and
nothing in the per-group scoring can surface it.

**`ov10_022BFE6C` wants the positive arm first.** Written as
`if (n >= a) return FALSE; …` MWCC predicates the pointer load (`ldrlt`) rather
than branching — 1100. Written `if (n < a) { …; return TRUE; } return FALSE;` it
is 0.

**`s32` versus `bool8` returns are per function, not a rule.** Three functions in
this batch needed `s32` because the target lacks the `and r0, r0, #0xff` that a
`bool8` return emits — and five others in the same batch genuinely have it.

## Landing tooling

**Fact.** The transcription hand-off is closed: `runbatch.py` persists each
winning source to JSON and `land_from_json.py` lands that exact text. Nothing is
retyped between scoring and landing.

**Fact.** Building that surfaced three regressions in the new lander, all caught
before the build except the last:

1. It extracted in **name order**, so each contiguous run split its file
   repeatedly — twelve destination files instead of five. Extraction must be in
   *address* order, so each successive function is at the head of the remainder
   and merges.
2. It dropped `land2.py`'s step adding `#include "util.h"` to generated headers,
   leaving `u32`/`s32` undefined.
3. A batch-module shortcut derived the extern list by splitting the context on
   `;\n` and keeping lines starting with `extern` — which silently drops the
   *first* extern of every group, because it is glued to the typedef preamble.

**Fact.** `hdrcheck.py` reported "all headers self-contained" while `u32` was
undefined in every one of them: it indexes `struct`/`enum`/`union` definitions
and does not know about typedefs. Worth tightening before it is trusted again.

## Open questions for a reviewer

1. **`asm/overlay_02.s` is unsplittable** — the headline item. Ten matched
   functions are waiting on it.
2. **`GetItemAnimation1` / `GetItemAnimation2`** index `s16` arrays at
   `[item_id * 2]` because the load is `ldrsh [base, id << 2]` — a stride of 4
   bytes over 2-byte elements. They are more likely two fields of one 4-byte
   record; `ov10_022C7A86` sits 2 bytes after `ITEM_ANIMATION_INFO`, which
   supports that reading and was not pursued.
3. **`struct move_anim_info`'s interior** is `field_0x0` (s32, read only through
   `ov10_022C9070`) and `field_0x8` (u8, the flag byte). The rest is padding to
   `0x18`.
4. **`ov10_022BFE54`'s predicate** is `a - 5 <= 1` on an unsigned argument, i.e.
   `a == 5 || a == 6`. The unsigned form is what matches; what 5 and 6 are is not
   established.
