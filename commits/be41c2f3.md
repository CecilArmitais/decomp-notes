## What this batch is for

**Fact.** The first *cleanup* batch. Earlier batches decompiled runs out of the
middle of large `.s` files, which splits each file and adds objects. This one
targets the leftovers instead: six small fragments, chosen so that finishing
them **deletes** the file rather than shrinking it.

**Fact.** All six `.s` files and their `.inc`s are gone, and `main.lsf` falls
from **1181 objects to 1175** — the first net reduction on this branch.

**Fact, the survey behind the selection.** Counting only *added* `.s` files
undercounts fragmentation: a file we extracted *from* is a remainder too. Across
all 72 `asm/*.s` this branch had touched, 6 were down to one function and 13 to
between two and five — several of them heads shrunk from far larger files
(`main_0203C774.s` 104 → 5, `main_020022C4.s` 68 → 5,
`overlay_17_0238A754.s` 44 → 5). This batch took the six that are small **and**
contain no malformed block and no region conditional.

## Matching

**Fact.** Nineteen matched on the first pass. `ov11_0230CCF0` scored 515 because
the short `return 0`, written first, is if-converted (`moveq r0, #0` / `popeq`)
where the target branches to a trailing block. Putting the long body in the `if`
gives 0 — the existing *make the early return the fall-through* entry in
`docs/MATCHING_TIPS.md`, applied unchanged.

**Fact.** `ov11_0230CCF0` copies 152 bytes (`9 × 16` plus `8`) out of
`ov11_0238A098`. Typed as `u32 field_0x0[38]` so the copy is 4-aligned and
emits the `ldmia`/`stmia` block loop the target has — the member-type rule from
the whole-struct-copy entry.

## Two things worth knowing for the next cleanup batch

**Fact — the object check is weaker here.** Six of the twenty are the last
function in their file. Emptying that file leaves them with no following
address, so `next_addr - this_addr` does not exist and `verify.py` cannot size
them: it covered 14 of 20. On a cleanup batch the matching build carries more of
the verification than usual.

**Fact — a lander bug this batch exposed.** The duplicate-declaration guard
treated the *call* `PlayMeById(a);` as an existing declaration: it ends in `;`
and starts with a letter once stripped, so the guard suppressed the real extern
and the build failed with `function has no prototype`. A declaration sits at
column 0 and a call is indented; the guard now skips indented lines. This would
misfire on any function whose name is first *used* in the destination file
before it is declared.
