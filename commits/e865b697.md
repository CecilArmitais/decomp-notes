## Shape of the batch

**Fact.** Second 5×10 stress test: fifty located as five groups of ten *before*
any matching, forty-nine matched (forty-eight on the first candidate), one build,
one commit. Branch total 555 → **604**.

| group | functions | landed |
|---|---|---|
| inventory menu window accessors | `ov10_022BCC7C` … `ov10_022BCDBC` | 10 |
| file/ROM transfer + bag init | `FileRom_StopDataTransfer` … `sub_0200CAE4` | 10 |
| overlay_16 + secret bazaar | `ov16_0238CC94` … `TalkToSecretBazaarNpcWithYesNoMenu` | 10 |
| Gt2 socket / connection accessors | `Gt2GetConnectionState` … `Gt2SetConnectionData` | 10 |
| forwarding veneers at `+4` | `sub_0202613C` … `sub_020261E4` | 9 |

**Fact, and the selection insight that made this batch cheaper than the last.** A
*contiguous run* costs **one** `.s` split, not one per function: after the first
extraction the next function sits at the head of the remainder and merges into
the source just created. The previous batch restricted itself to runs at file
*boundaries* to avoid splits at all; that was over-cautious and forced larger,
messier functions. Runs anywhere in a file are nearly as cheap, which opened up
much smaller candidates — 40–77 instructions per group of ten.

**Fact.** Single-function `.s` files went 59 → 60, the one extra coming from the
gap left by the function that did not land.

## Matching findings

**`GetDamageSource` returns `s16`.** The `lsl #16` / `asr #16` before its return
is the *return conversion*, not a cast in the body. `s16` return with an `s32`
parameter scores 0; returning `s32` and writing `return (s16) a;` also scores 0,
but the early-return arrangement of the same logic scores 710 and the original
`s32`-return shape scores 510.

**`ov29_022F05B4`'s arms were inverted.** Fourth instance of the same rule
(`sub_02009DCC`, `DoMoveSwallow`, `sub_0202C75C` are the others): MWCC lets the
*first arm written in the source* fall through, so which arm comes first is a
source decision the bytes record.

**`TalkToSecretBazaarNpcStandard` vs `ov29_022F0618`.** These two differ by
exactly one instruction — `mov r3, #0` against `mov ip, #0` — and that is the
whole story. `r3` is the **fourth argument register**: the `Standard` variant
overwrites it, so it passes `0` for that parameter, while the other preserves it
and forwards its own. Same callee, different arity at the call site. A register
choice that looks arbitrary was the argument list.

**`IsInventoryMenuActive` returns `s32`, not `bool8`.** `bool8` appends an
`and r0, r0, #0xff` the target does not have (100).

**Inference.** `Gt2GetRemoteIP` reads offset 0 while `Gt2GetLocalIP` reads offset
4, and `Gt2GetSocketSocket` reads offset 0 as a different kind of value — so the
Gt2 functions take **two** distinct types, not one. Modelled as
`struct unk_0230E3E8` (connection) and `struct unk_0230E420` (socket). The names
`Gt2*` are pre-existing; the split is read off the offsets.

## Not landed: `sub_0202614C`, at 300

**Fact.** The target takes the address of its stack local **before** the first
store:

```asm
	add r3, sp, #0      @ &v
	str r1, [sp]        @ v.0 = a
	mov r1, r3
	add r0, r0, #4
	str r2, [sp, #4]    @ v.1 = b
	bl sub_02020B60
```

Every candidate computes the address *after* both stores (`add r1, sp, #0`),
which is one instruction fewer in a different place — a stable **300**.

**Falsified** (all 300): a `struct` local with `&v` at the call, a pointer local
initialised to `&v`, storing *through* that pointer, a two-element `s32` array,
a reversed store order, and hoisting the destination into its own local.
**Falsified** (905): taking the pair as a struct **by value**, which makes MWCC
push `r0`–`r3` on entry. **Falsified** (775): initialising the struct at
declaration.

**Untried**: reading `sub_02020B60`'s own body to learn what it does with the
pointer (it may write through it, which would change the local's liveness), and
the callers of `sub_0202614C`, which have not been looked at.

## Four landing failures, all tooling, and two fixes applied to the tools

**Fact.** Matching went well — 48/50 on the first candidate. The **landing**
failed four times, none of it a wrong candidate:

1. **Externs sprayed across files.** The landing spec carries one extern list per
   entry and it was filled per *group*; two groups span two destination files, so
   both files received the union. `src/overlay_16_0238CC94.c` got the secret
   bazaar's externs, which name a `struct entity` that file never declares.
2. **A guard that was dead on arrival.** The duplicate-declaration guard added in
   [`7658e4f9`](7658e4f9.md) contained a literal **backspace byte** where `\b`
   was intended — the shell had eaten the escape when the patch was written. The
   pattern therefore matched nothing, which is exactly why it reported no skips
   and looked like it was working. Found by testing it rather than trusting it.
3. **A non-self-contained header.** `include/main_02008194.h` names
   `struct file_stream *` in a prototype without including `file.h`, so the
   struct is declared *inside the parameter list* and is a different type from
   the real one. The error is maddeningly unhelpful:

   ```
   was declared as: 'void (struct file_stream *)'
   now declared as: 'void (struct file_stream *)'
   ```

   This trap is recorded in `CLAUDE.md` as already having been hit three times.
4. **Pruning scope.** Removing the unused externs from (1) initially ran over the
   whole tree; it was re-scoped to this batch's eight files before building, so
   nothing unrelated was touched — unlike the equivalent mistake on
   [`7658e4f9`](7658e4f9.md), which had to be reverted.

**Two fixes, in the tooling rather than in a note**, following the same
principle that closed the redeclaration recurrence:

- The duplicate-declaration guard is repaired and **tested directly** — it now
  matches a real declaration and rejects a substring.
- A new `hdrcheck.py` builds a type→header index across `include/` and reports,
  for any header, each type it names but neither defines nor reaches by include,
  with the exact `#include` to add. Verified against the real bug: with `file.h`
  removed it reports `struct file_stream -> add #include "file.h"`.

**Still outstanding, deliberately not attempted mid-batch.** The root defect
behind failure (1) is that externs are specified per group rather than per
function. The correct fix is to derive each function's externs from the symbols
its own body actually references, which would make group and file boundaries
irrelevant.
