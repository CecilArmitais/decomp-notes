## Decompiled

**Nothing.** This is a correction commit, and the clearest example on the branch
of the rule *check the canonical type source before inventing anything*.

## What went wrong

**Fact.** The previous commit declared `struct unk_020B0A48` for the records
`TEAM_MEMBER_TABLE_PTR` points at. That global is **already typed in the tree**
as `struct team_member_table` (`common.h`), whose `members[]` elements are
`struct ground_monster` -- a 0x44-byte record whose field at `0x4` is the
documented `s16` monster id.

So the placeholder was a redundant reinvention of an existing type -- **and** it
declared `TEAM_MEMBER_TABLE_PTR` a second time, conflicting with the `extern`
that two other already-decompiled files use.

## The fix

**Fact.** `TEAM_MEMBER_TABLE_PTR` becomes `struct team_member_table*`; the six
accessors return `struct ground_monster*`; the nine reads that fed `*out`
through `->field_0x4` now read `->id` (or `->members[i].id` for the
table-indexed pair). `struct unk_020B0A48` is removed and `common.h` included.

**Fact, byte-neutral.** `members[]` sits at offset 0 of `team_member_table`, and
`ground_monster` has the same 0x44 stride and `0x4` field as the placeholder, so
every read computes an identical address. Confirmed by a matching build.

## Why this is more than a tidy-up

**Inference, but well supported by the diff.** It makes the output type legible
*from the decompilation itself*: every value written to `*out` in `sub_0206549C`
now reads in-tree as a monster id -- a `ground_monster.id`, a monster-valued
script variable, or an entry of a table that decodes to species. That is a
correctness argument a reviewer can check by reading the C, which a placeholder
never affords.

## The lesson

The failure was **not** a bad name -- the layout was correct. It was **not
looking first**. A `grep` in `pmd-sky/include/` before declaring anything is
cheap; skipping it cost an entire extra commit and briefly put a conflicting
declaration of a shared global in the tree.
