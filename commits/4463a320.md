**These are callees, taken before their callers on purpose.** A matched callee

## The aliased-symbol trap, stated early

**Fact.** `sub_02064FFC` and `sub_02065014` index the same 12-byte table.
`EVENTS` already exists in the tree; its record type is declared here as
`struct unk_020A5488`.

**Fact, and important when diffing against the asm.** `_020A5490` is a separate
`.global` sitting at `EVENTS + 8` -- *inside the first record*. The target's
literal pool therefore reads `.word _020A5490` where this source emits
`EVENTS+0x8`. Both resolve to the same address; the matching build is what
confirms it.

The same phenomenon later cost a build on this branch -- see
[`7f6977e2`](7f6977e2.md). The two are worth reading together.

## Argument structs with no global

**Fact.** `sub_02064F94` walks an array calling `sub_0201E380`; `sub_02064FE4`
is a tail call into it. Their two argument structs have **no global**, so per the
placeholder convention they are named for the function that receives them:
`struct unk_02064F94` and `struct unk_02064FE4`.

## Naming, and an inference explicitly refused

Nothing named for meaning. Local names were kept *structural* on purpose: `data`
is a cursor over 4-byte records, `count` is the loop bound, `value` is the field
the comparison reads. `sub_0201E380`'s parameters are positional, because only
its call site was understood, not its body.

Anything more specific would have been inferred from code two calls downstream
rather than read off this asm -- so it was not written.
