**This completes the actor cluster.** `asm/main_0206549C.s` is removed entirely
and `main.lsf` drops the object.

**Fact.** It calls `sub_02065050` to resolve the entity id in place, then maps
the result to a monster id written through its second argument: kind 3 resolves
against the loaded unit or adventure NPC list; everything else dispatches through
a switch over script entity ids, reading team members, script variables or
`SPECIAL_ACTORS` slots.

## `enum monster_id` gains `MONSTER_INVALID = -1`

**Fact.** Same mechanism as `ENTITY_NONE` in the previous commit: this function
reads nine `SPECIAL_ACTORS` slots of that type with `ldrsh`, and an unsigned enum
compiles those to `ldrh`.

**Fact.** The name avoids `MONSTER_NONE`, which the `_MONSTER_ID_GENDERED` macro
already defines as `0`.

**Fact, verified in isolation.** Added alone with nothing else modified; ROM
still matches, so it is byte-neutral for all existing code.

**A reversal, and reviewers should see it as one.** [`b9893192`](b9893192.md)
explicitly *declined* to add this sentinel, preferring not to diverge from
pmdsky-debug. Two commits of evidence later it was added. That is the branch
changing its mind under evidence rather than a settled position -- and it is
exactly the sort of cross-cutting change (an enum shared tree-wide) a reviewer
should weigh independently.

## `struct unk_020A7FF0.field_0x2` becomes `s16`

**Fact.** The switch's default case reads it with `ldrsh`. That is the third
field corrected this way, after `field_0x0` and the `script_entity_id` slots.

## A placeholder introduced here and removed in the very next commit

`struct unk_020B0A48` was declared for the 0x44-byte records
`TEAM_MEMBER_TABLE_PTR` points at, sized by counting to the next label in the
data. The **layout was right**; declaring it at all was the mistake. See
[`40325982`](40325982.md).
