## The one that is not here

**Fact.** `GetCoroutineInfo` reaches **30** — two rows — and is left as
assembly. Every instruction matches; the base pointer and the record pointer
are swapped between `r2` and `r3`:

```asm
@ target                          @ candidate
	ldr r2, [r0]                     	ldr r3, [r0]
	add r3, r2, r1, lsl #1           	add r2, r3, r1, lsl #1
```

**Fact, what moved it.** The target computes `idx * 3` as an integer
(strength-reduced to `add r1, r5, r5, lsl #1`) and scales it separately.
Indexing `p[idx * 3 + 2]` folds the whole thing into one `mla` by 6 instead —
**500**. Forming the record pointer through a precomputed `n = idx * 3` gives
the target's shape — **30**.

**Fact, what did not move it**: six declaration orderings of `n`/`p`/`rec`;
dropping `p` and re-reading the global; `u32` for `n`; inlining `idx * 3` into
the pointer expression (worse, 500); typing `rec` as `s16 *` (worse, 420);
assigning `p` before `n`. Eight structural variants in total.

**This is the limit of what was tried, not a property of the function.** The
remaining difference is a register assignment with no evident source-level
lever; the next person should not assume the listed directions are exhaustive.

## Matching findings

### A switch needs a fourth case before MWCC splits

**Fact.** `SetAnimationLiveObject` selects on `anim & 0x700` with cases
`0x100`, `0x200`, `0x400`. Three cases give a flat compare chain — **1780**.
Adding `case 0x300:` with an **empty body** produces the target's binary split
at `0x200` — **0**. The empty case leaves no trace in the emitted code except
the chain's shape.

**Second batch running** in which that closed a function; see `ov18_0238BFA8`
in [`e6530b43`](e6530b43.md), where the extra case shared `default`'s body.

### `x == A || x == B` on adjacent constants folds to a range test

**Fact, measured on `ov17_0238B10C`.** The target has `cmp r0, #4` /
`cmpne r0, #5`. Every `||` spelling folds to `(x - 4) <= 1`:

| form | score |
|---|---|
| `mode == 4 \|\| mode == 5`, as `enum` / `s32` / `u32` | 515 / 405 / 405 |
| operands reversed, and Yoda order | 405 |
| non-short-circuit `\|` | 910 |
| `mode != 4 && mode != 5` (arms swapped by MWCC) | 210 |
| `!(mode != 4 && mode != 5)` | **0** |

**Inference, and flagged as such.** The double negation is the form that
matches; it blocks the fold *and* keeps the positive arm as the fall-through,
which the plain negated form gets backwards. Whether retail's source read that
way is **not** established — the bytes cannot separate it from any other
construct with those two properties.

## Tooling

**Fact.** `hdrcheck.py` now also checks `.c` files. A source can use a type its
own header never names — which is how a `.c` referencing `struct unk_0238C950`
reached the compiler in `e6530b43`. Of the five problems caught before any build
this batch, **four were in `.c` files** the header-only check could not see.

**Fact, a real tool bug.** Struct definitions landed in **reverse dependency
order**: each block is inserted directly after the include guard, so the last
one written ends up first. `struct unk_0201BCCC` was therefore defined ahead of
the two structs it contains, making those members incomplete types. MWCC reports
this as *"illegal implicit conversion from `signed char *`"*, which points
nowhere near the cause. Fixed by walking the context's struct list backwards —
the scratch compiled, so its order is already dependency-correct.
