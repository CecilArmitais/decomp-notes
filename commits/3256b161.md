## Decompiled

`GetAppointedLeaderMemberIdx` and `sub_02056914`, the last two accessors of this
cluster, from `asm/main_02055894.s`.

**Fact.** Both resolve the appointed leader through the roster region of
`team_member_table`: read the active team from `active_team`, index the three
`number_active_team_members` fields by it, and use that value to index
`active_roster_member_idxs`. `GetAppointedLeaderMemberIdx` returns the resulting
member index, or `-1` when the first read is `-1`. `sub_02056914` is its pointer
counterpart, returning `&members[index]` or `NULL` when either read is `-1` --
the same index/pointer pairing as `GetHeroMemberIdx`/`GetHero`.

## Three scalars indexed as an array

**Fact, and the one thing here a reviewer should look at closely.** The three
`number_active_team_members` fields are **separate scalars** in `common.h`, but
are indexed here as an array, which is what the asm does. The expression relies
on them being contiguous.

**Inference.** The struct layout guarantees that contiguity, so the C is
well-defined in practice for this compiler. Whether upstream would rather model
those three fields *as* an array is a legitimate design question this commit does
not settle -- it chose not to change a struct shared with the rest of the tree.

## File mechanics

**Fact.** Each function sits in the middle of `asm/main_02055894.s` and they are
not adjacent, so each extraction splits the file: trailing functions move
verbatim into `asm/main_020568DC.s` and `asm/main_02056960.s`, and `main.lsf`
gains four objects.

and `sub_0206549C` call them and were rebuilt to confirm byte-identity.
