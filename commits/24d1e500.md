## The shared-header change

`3fc6d8bd` gave `move_category` explicit padding on the reading that it is a
1-byte enum. This function's own store shows the field is written as a word, so
the padding model was replaced by `s32 move_category;` (the struct stays 0x54
bytes; the previous note's word-access evidence from `asm/overlay_29_022E0378.s`
and `asm/overlay_29_022E335C.s` agrees). The modifiers' signedness is the same
kind of correction as `5271b77a`'s: the tree's `s8` came from pmdsky-debug, the
loads are unsigned. Both are deviations from the upstream declarations and are
worth raising there; the fields are conceptually signed counts (−2..+2), which
is why upstream chose `s8`, but the codegen needs `u8`.

## The match

Scratch `current_score: 0` for all three regions, each against a context
generated from the landed file's own includes with the real compiler
(`build-tools/mkctx.sh`), and the landed translation unit compiles clean under
the tree's full `-W error` set. The whole-function objdump of a plain compile is
instruction-for-instruction equal to the retail listing.

**How it was reached.** ~114 rounds are recorded in the workspace's
`wip/CalcDamage/README.md`. The function was byte-identical outside one basic
block from round 15 on; that block (the offense/defense ability multiply, eleven
instructions) resisted every C-level respelling because it is decided by three
compiler internals — IRO's expression propagation, the pre-alloc list scheduler
and the allocator's simplify order. Those were instrumented under gdb, modelled,
and finally *patched*: overwriting one interference degree inside the compiler
made the rest of the pipeline emit retail, which pinned the residue to one
quantity before the C was written.

## A construct that is match-derived, not recovered source

The block is spelled as

```c
s32 calc[2];  s32 dv;  s32 p;
volatile s32 *po; volatile s32 *po2; volatile s32 *pd;
po = &calc[0]; po2 = &calc[0];        /* far above the block */
...
pd = &calc[1];
p = *po * off_ability_mult;
dv = *pd;
*pd = dv * def_ability_mult;
*po2 = p;
if (off_ability_div != 1) { *po2 = p / off_ability_div; }
if (def_ability_div != 1) { pd = &calc[1]; *pd = *pd / def_ability_div; }
```

Each element removes one measured obstacle: `&calc[1]` is an address
*expression* (an address constant is copy-propagated unconditionally and the
pointer folds away); `dv` keeps two references so the second propagation run
cannot dissolve the pointer; the `volatile` pointees stop `dv` being propagated
and chain the two stores in program order in the scheduler (nothing else keeps
the offense store after the defense store); `p` with two uses keeps the offense
load ahead of the address computation; defining `pd` first and giving the load
its own dying pointer `po` decides the allocator's colouring order. It is
ordinary C and compiles to the bytes, but it is not a claim about what the
original source looked like; the reviewer may prefer a plainer spelling if one
satisfying the same four conditions is found (`docs/MATCHING_TIPS.md` in the
workspace lists them).
