## Decompiled

| function | address |
|---|---|
| `GetWindowIdSelectedItemOnPage` | `0x0202AB80` |
| `CloseSimpleMenu` | `0x0202B4C4` |
| `IsSimpleMenuActive` | `0x0202B520` |
| `CheckSimpleMenuField0x1A0` | `0x0202B540` |
| `GetSimpleMenuField0x1A4` | `0x0202B558` |

**Fact.** These are the simple-menu counterparts of the parent-menu accessors in
[`3fc19ec7`](3fc19ec7.md) and reach the same window contents through
`GetWindowContents`, so they reuse `struct unk_0202AAA8`, which gains a field at
`0x1A4`.

**Fact.** `IsSimpleMenuActive` tests states **7 and 8** where the parent-menu
version tests **8 and 9**. As there, the state is bound to a local so the field
is loaded once.

## Consolidating declarations rather than repeating them

**Fact.** `DeleteWindow` moves into the shared header and `MemFree` is taken from
`main_02001188.h`, rather than each source declaring them again. Two of these
functions need both.

Stated at the time and worth repeating: **a second local copy of a prototype is
the kind of disagreement no build can report.**

## The precommit.py bug, seen from the affected side

**Fact.** The asm files this split produces keep upstream's jump-table
annotations. **An earlier run of `precommit.py` stripped them**, having discarded
the removals that its rule 2 matches against.

That tooling bug is fixed separately in the workspace repo, and the **158
comments in this split are intact here**. The restoration of what earlier commits
