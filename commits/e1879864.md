## `sub_020564B0`

**Fact.** Takes a member index and reports whether it is the appointed leader's.
It **repeats** the roster read `GetAppointedLeaderMemberIdx` performs --
`active_team` selects one of the `number_active_team_members` fields, and that
value indexes `active_roster_member_idxs` -- and compares the result against its
argument, returning false if either the argument or the intermediate is `-1`.

**Worth noting:** it repeats the computation rather than calling the accessor.
With `-inline on,noauto` that is not an inlining artifact; the retail source
genuinely duplicated it.

**Fact.** With this, both NPC-collection filters are accounted for:
`GetAdventureNpcIds` excludes the appointed leader, `GetUnitNpcIds` the three
main characters.

## A struct named for its function, and the cast it forced

byte pointer at `0x1c`. **No global has that type** -- callers pass an interior
offset of whatever `_020AFC70` points at -- so per the placeholder convention it
is named for the function that receives it: `struct unk_0201E380`, fields named
for offsets.

**Fact.** The parameter was previously declared `u8*` while only the call site
was understood, so `sub_02064F94` now **casts at that call site**; it was rebuilt
to confirm byte-identity. `src/main_02056D70.c` likewise drops its local `extern`
for `sub_020564B0` in favour of the new header.

Another instance of the same lesson as [`6371544d`](6371544d.md): a call site
shows far less than a body, and the correction lands on the caller.
