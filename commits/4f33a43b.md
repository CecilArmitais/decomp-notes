## The scope lesson behind this commit

Before this landed, the conclusion had been drawn that **overlays could not be
decompiled here**, on the evidence that `overlay_11` had no `src/` files.

That conclusion was **wrong**, and instructively so: ~110 overlay sources already
existed, `extract_function.py` supported overlays natively, and the function
landed first try once actually attempted.

**One missing file is not evidence about a category.** A negative claim about
what is possible needs evidence about the general case. This is now written into
the project's procedure as a standing rule.

## Two deliberate refusals to over-assert

**`ov11_02324FA0` is declared `u8[0x20]`, not a struct.** The symbol is
`.space 0x20` in the data, so **the size is a fact**. Other functions in the
overlay touch offsets `0x0`, `0xc`, `0x10`, `0x14` and `0x1c` -- none of them
decompiled -- so a struct would have to **invent a layout** around the single
field this function reads. The array asserts only the size.

**The return type is `u8`, not `bool8`.** The load is `ldrb`, so the width is a
fact, but every candidate return type produces identical bytes here. `bool8`
would additionally assert the value is a *truth value*, which is only an
inference from the two callers testing it in a condition. `u8` states what is
known and nothing more.

Both of these are worth holding up as the standard: **choose the type that
asserts least among those that produce the right bytes.**
