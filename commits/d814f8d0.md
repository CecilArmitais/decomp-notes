thrown- and eaten-item dispatcher: an item-catcher preamble, the sticky-item

## Landing shape

**Fact.** Last of ten functions in `asm/overlay_29_0231B33C.s`; `main.lsf` puts
`src/overlay_29_0231CBC8.o` next, so `extract_function.py` merges rather than
splits and **`main.lsf` is unchanged**.

One manual fix was needed and was predicted: the tool inserts a declaration at
the first non-blank non-`#` line of the header, which was the *comment* on
`EntityIsValid__0231CBC8`. Left alone, that comment would document the wrong
function. The new declaration was moved below it; the comment itself was not
touched.

## The stale declaration, and why replacing it is a check

**Fact.** `src/dungeon_projectile_throw.c` declared `ApplyItemEffect` itself
(`extern void ApplyItemEffect(char, u8, u8, struct entity *, struct entity *,
struct item *)`) and calls it. That `extern` is gone and the file now includes
the new header.

This is the case `CLAUDE.md` describes under *the stale declaration is often not
yours*, and it is worth more than tidiness here: that file is a landed,
already-matching object, and **parameters 1-3 are exactly where a wrong spelling
would surface**. Its rebuild in all three regions is therefore evidence about
the signature. It is agreement, not proof — see the open questions.

## A general fact about MWCC's jump tables

`case ITEM_NOTHING:` is written explicitly above `default:` even though table
entry 0 points at `default`. That was disputed during review and settled by
**surveying all 786 `add<cc> pc, pc, rX, lsl #2` dispatches in `asm/`** (719
with a decodable table) rather than by judgement:

- 105 tables carry a rebase `sub rX, rX, #K`, and **104 of those have a real
  case at index 0** — the base equals a labelled case.
- Rebases occur for offsets as small as 3, so there is no "too small to bother"
  rule; yet 40 tables have 3-7 *leading* default entries with **no** rebase.
  Offset 3 appears both rebased and un-rebased, which no threshold rule explains.
- 82 tables have *trailing* default entries (one has eight). Padding upward buys
  nothing.

**Conclusion:** the table spans the minimum to maximum *labelled* case, and
leading and trailing default entries are explicitly written `case` labels
sharing `default`'s body. This is a statement about the compiler, not about this
function, and it is worth knowing for the next switch-heavy target.

## Two other structural facts

- **The category-5/10 test that skips the switch is an `if`/`else` whose `else`
  arm is the entire switch.** There is no branch construct that jumps past a
  183-case switch; both arms fall into the shared tail.
- **Case emission order is source order and is not ascending** — 8 before 7, 77
  before 74, 136 before 113, 182 before 104, 180 before 179, `default` last.
  This is the single largest structural constraint in the function.
