## `DoMoveTickle` — the stall, and what closed it

**Fact, restated from the earlier note.** The target reaches `ATK_STAT_IDX`
through `SPATK_STAT_IDX`'s pool entry:

```asm
	ldr r2, _02327740 ; =SPATK_STAT_IDX
	ldr r2, [r2, #4]
```

Naming `ATK_STAT_IDX` directly emits offset 0 and a different pool word — two
rows, score **15**.

**Fact.** The two globals are adjacent in `asm/overlay_29_rodata_02352A6C.s`,
in that order, four bytes apart:

```asm
	.global SPATK_STAT_IDX
SPATK_STAT_IDX:
	.byte 0x01, 0x00, 0x00, 0x00
	.global ATK_STAT_IDX
ATK_STAT_IDX:
	.byte 0x00, 0x00, 0x00, 0x00
```

So `ATK_STAT_IDX` **is** `SPATK_STAT_IDX[1]` as a matter of layout, not
interpretation.

**Fact.** Declaring the symbol with array type and indexing it scores **0**:

```c
extern const struct StatIndex SPATK_STAT_IDX[];

struct StatIndex stat = SPATK_STAT_IDX[1];
```

**Fact.** Three spellings that reach the same address do **not** work, which is
what makes this a type question rather than an expression question:

| spelling | score |
|---|---|
| `SPATK_STAT_IDX[1]` on an array-typed `const` extern | **0** |
| `*(SPATK_STAT_IDX + 1)`, same declaration | **0** |
| `(&SPATK_STAT_IDX)[1]` on a *scalar* extern | 60 |
| `p = &SPATK_STAT_IDX; p[1]` | 60 |
| `SPATK_STAT_IDX[1]` on a **non-`const`** array extern | 60 |

An array-typed extern is already the in-tree idiom for exactly this — `extern
struct dungeon *DUNGEON_PTR[];` appears throughout `overlay_29`, and
`main_0205B690.h` carries a `union` commented "Stupid hack but it's needed for
some matches."

**Inference, and the open question.** The most likely original source is a
**single array object** that pmdsky-debug has split into two separately named
symbols — the retail C probably said something like `STAT_IDXS[1]`. This commit
does not introduce that symbol, because merging two `.global`s into one array is
a data-symbol identification, not a decompilation, and it was not the assignment.
What is landed reproduces the bytes using only symbols that already exist.

**Fact, and a wart a reviewer should weigh.** `SPATK_STAT_IDX` is now declared
two different ways in the tree: array type in `src/overlay_29_023276B4.c`, scalar
type in **15** other `overlay_29` sources. The declarations never meet in one
translation unit so nothing catches it, and `DoMoveMetalSound` — which shares the
file — was converted to `SPATK_STAT_IDX[0]` and still matches. It is
nevertheless an inconsistency, and the clean fix is the array symbol above.

## `TeamMemberHasExclusiveItemEffectActive` — a stale declaration retired

**Fact.** The tree already had a provisional declaration of this function,
written from a call site by an earlier contributor:

```c
bool8 TeamMemberHasExclusiveItemEffectActive(u8);   /* src/overlay_29_02338548.c */
```

**Fact.** The real parameter is `enum exclusive_item_effect_id`: the value is
passed straight through, unmasked, to
`ExclusiveItemEffectIsActive__0230F8AC(struct entity *, enum
exclusive_item_effect_id)`. The provisional line is deleted and the file now
includes the new header.

**Fact.** `u8` also scores 0 in isolation — the callee's signature, not the
bytes, is what settles this. But `u8` does **not** survive the real build:
`-W all -W pedantic -W error` rejects the implicit `u8`→enum conversion at the
inner call. The scratch cannot see that, because it does not use the build's
warning flags. This is a second instance of the general point that a score of 0
on a scratch is necessary and not sufficient.

**Fact, and a pleasing corroboration.** The two callers pass `0x5e` and `0x5f`,
which resolve in `include/item.h` to:

```c
EXCLUSIVE_EFF_MORE_KECLEON_SHOPS = 94,   /* 0x5e */
EXCLUSIVE_EFF_MORE_HIDDEN_STAIRS = 95,   /* 0x5f */
```

matching `UpdateShouldBoostKecleonShopSpawnChance` and
`UpdateShouldBoostHiddenStairsSpawnChance` by name. Both call sites now use the
enumerator rather than the literal; this was **forced** by the warning flags
above, not chosen for readability.

## `UpdateShouldBoostHiddenStairsSpawnChance` — a twin already in the file

**Fact.** `UpdateShouldBoostKecleonShopSpawnChance`, three functions up in
`src/overlay_29_02338548.c`, is the same function against the neighbouring field
and was already matching. The candidate copies its shape verbatim and scored 0
first try. Both the array (`DUNGEON_PTR[0]->…`) and scalar (`DUNGEON_PTR->…`)

## `DoMoveSwitchPositions` — `< 1`, not `== 0`

**Fact.** The field is `struct monster::exp_yield`, a `u8`, so `< 1` and `== 0`
are the same predicate. They are **not** the same code: `< 1` scores **0** and
`== 0` scores **405**. The target's `cmp #1` / `movlo` / `strlob` is the
literal transcription of `< 1`.

**Inference.** The move raises a zero exp yield to 1 before swapping places.
Why is not established here.

## `GetMobilityTypeAfterIqSkills` — a whole function inside `#ifndef JAPAN`

**Fact.** The entire `.s` file was one function wrapped in `#ifndef JAPAN`, so
the guard moves into the `.c` **and** around the prototype in the `.h`. JP does
not build this function at all.

**Fact.** `IQ_ALL_TERRAIN_HIKER = 12` and `IQ_ABSOLUTE_MOVER = 13` are the
existing enumerators for the two `IqSkillIsEnabled` calls, and `MOBILITY_HOVERING
= 2` / `MOBILITY_INTANGIBLE = 3` for the two assignments — all read off
`include/enums.h`, none invented.

**Fact.** Both the `&&` chain and the nested-`if` spelling score 0; the `&&`
form was kept.

## Region conditionals

**Fact.** Three of the five carried a region conditional in the asm, so this
batch was verified on **all three** ROMs rather than US alone:

| function | conditional | handled by |
|---|---|---|
| `GetMobilityTypeAfterIqSkills` | whole function `#ifndef JAPAN` | a guard in the `.c` and `.h` |
| `DoMoveSwitchPositions` | field at `0x107` (JP) / `0x108` | existing `#ifndef JAPAN` in `dungeon_mode.h` |
| `TeamMemberHasExclusiveItemEffectActive` | `0xa84` (JP) / `0xb28` | existing conditional in `dungeon.h` |
| `UpdateShouldBoostHiddenStairsSpawnChance` | `0xa81` (JP) / `0xb25` | ditto |

**Inference.** For the last three the C is region-neutral — the byte offset
difference is entirely absorbed by `#ifndef JAPAN` around `struct monster::
in_action`, which exists only outside JP and shifts everything after it by one.

## Tooling

**Fact.** `build-tools/build.sh` gained a `TARGETS` variable so a batch with a
region conditional can be verified in one invocation
(`TARGETS="eu jp" build-tools/build.sh …`); US is always built. Previously
verifying EU/JP meant a hand-written `docker run`.
