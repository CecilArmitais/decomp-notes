**This is the group `c9d0c766` could not land.** The full reasoning — why
`-O4,s` inlines a small callee that `-O4,p` does not, the minimal reproducer,

## What the landing needed

**Fact.** Three coordinated changes, and **no build-system edit**: `Makefile`,
`common.mk`, `config.mk` and `tools/` are byte-identical to `upstream/main`
across the whole branch.

1. The file goes to `lib/src/overlay_00_022DB1A4.c`, so the lib compile rule
   matches by path. `LIB_SRC_SUBDIR` already contains a plain `lib/src` that did
   not exist on disk, so creating it needed no makefile change.
2. `main.lsf` swaps one object for two inside `OVY_0`:

   ```
   -	Object asm/overlay_00_022DB1A4.o
   +	Object lib/src/overlay_00_022DB1A4.o
   +	Object asm/overlay_00_022DB2F8.o
   ```

3. The ten functions must be emitted in **address order**.

**Fact.** A `lib/` object links into an *overlay* section without complaint,
although all 135 pre-existing `Object lib/…` lines sit under `Static main`. It
also receives the full defines despite `$(ALL_LIB_OBJS): DEFINES = $(GLB_DEFINES)`
in `common.mk`; an earlier claim here that lib objects lose `-DNORTH_AMERICA`
was wrong. Irrelevant either way — none of these ten carries a region
conditional.

## The ordering trap, which cost a build

**Fact.** The first attempt had every function the **right size** and
**byte-identical to the assembled original**, and still failed `OVY_0` — because
they were emitted in the wrong order, so every call into the group resolved
somewhere else. A script moving the functions between files recorded each
block's position with `str.index` against a string it was still mutating, and
sorting those positions scrambled them.

**The signature in a binary diff** is each `bl` retargeting by a *different*
delta (`Dwc_IsBuddyFriendData` +176, `Dwc_GetFriendDataType` +152). A block that
merely moved retargets them all by the same amount.

**Fact.** Neither a per-function size check nor a per-function byte comparison
can see this — both compare symbols in isolation. `verify.py` now checks
emission order explicitly.

## Open question for a reviewer

**Whether `lib/` is the right home at all.** A matching ROM validates the
*bytes*, and both candidate explanations predict identical bytes, so the build
cannot choose between them. The discriminating test — split the group across
`src/` objects at the boundaries the call shapes imply, and check the sizes
under `-O4,s` — has not been run. If it reproduces them, this code belongs in
`src/`, split, and the file should move.
