## What changed

```c
/* src/overlay_29_02308FBC.c */
struct unk_023535DC {
    u8 field_0x0;
-   u8 filler1[3];
+   u8 field_0x1[3];
    s32 field_0x4;
    bool8 (*field_0x8)(struct entity *attacker, struct entity *defender, s32 a);
-   u8 filler2[4];
+   u8 field_0xc[4];
};

struct unk_022C593C {
    s16 field_0x0;
-   u8 filler[10];
+   u8 field_0x2[10];
};
```

## Why

**Fact.** Both structs were introduced by this branch, so their member names were
ours to choose, and CLAUDE.md prescribes `field_0x<off>` for the members of a
placeholder struct. `filler`-style names have almost no precedent: at `a3d64122`
the only ones in the whole tree are `fillerForNow` and `fillerForNow2` in
`include/ground_bg.h` (2 occurrences), against **2515** uses of the
`field_0x<off>` form — 2071 lowercase-hex and 444 uppercase-hex.

**Fact.** The offsets are forced by the preceding members, not chosen:
`u8 field_0x0` then a 3-byte gap to the `s32` at 0x4 gives `field_0x1[3]`; the
function pointer at 0x8 is 4 bytes, so the trailing array is `field_0xc[4]`; and
`s16 field_0x0` gives `field_0x2[10]`.

**Fact.** Neither member is referenced anywhere in `src/` or `include/` — they
are padding. No type and no declaration order changed, so no layout can move.

## How it was verified, and why not by ROM build alone

The change cannot interact with a region macro (it is an identifier rename, and
neither struct contains a preprocessor directive), so the meaningful check is
object identity, not a ROM checksum. That check was run **per region**, which is
not redundant here: the three objects are *different sizes* (19408 / 19552 /
19312), so `src/overlay_29_02308FBC.c` genuinely does compile differently per
region — it is simply insensitive to this particular edit.

**Method note, recorded because the first attempt was wasteful.** A full
three-region ROM build was run first and a second was started merely to capture
output the first had truncated. That was ~20 minutes to improve the wording of
this commit message, for a change already proved byte-neutral at object level.
The right-sized check for a declaration-only edit is the object diff
(~15 s/region); the ROM build is the gate for *matching* work, not for a rename.
