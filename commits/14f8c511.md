## What is and is not established

**Fact.** `DoMoveBlock` forwards to `TryInflictShadowHoldStatus` with the same
argument as `DoMoveShadowHold` in the previous batch. Block and Shadow Hold
share an implementation; the wrappers are byte-identical apart from their
symbol.

**Inference, and weak.** Unlike the previous batch, **none** of these ten
helpers is declared anywhere in the tree, so every prototype here was written
from the call site. Seven take only `(user, target)`, which the asm establishes.
The two that take a third argument — `TryInflictTauntStatus` and
`TryInflictShadowHoldStatus` — pass `0`, and the parameter name `onlyCheck` is a
**guess** carried over from `TryInflictParalysisStatus`, which is declared in
`move_orb_effects.h` with that name in the fourth position. Nothing here
verifies it, and the position differs.

The `void` return type on all ten externs is likewise unverified: the wrappers
discard whatever comes back, so the asm cannot distinguish `void` from a
value-returning helper. A `bool8` return would compile identically here.

## Process

Same as the previous batch: context preprocessed from the real headers, each
candidate scored in a scratch before landing, and every
`arm_func_start`/`arm_func_end` block checked for preprocessor directives —
none found, so only the US ROM was built.

**Fact.** Two nearby wrappers were deliberately skipped because they are a
different shape: `DoMoveGrudge` and `DoMoveDamageStealItem` are **tail calls**
(`ldr ip, =Func` / `bx ip`) rather than call-and-return-TRUE. They need a
`return f(...)` form and will not match the template used here. They remain in
asm.
