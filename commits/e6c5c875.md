## The signature a function's own bytes cannot decide

**This is the commit's most reusable finding.**

`Arm9LoadUnkFieldNa0x2029EC8` keeps the **two-parameter** prototype already
declared in `overlay_31_02382820.c`. Its body reads only the first argument --
the second register is overwritten with the table address before any use -- so
**the function's own bytes do not distinguish a one-parameter form from a
two-parameter one, and both score 0** against the target.

**The call site does distinguish them.** `overlay_31_02382820.c` passes two
arguments and already matches, so the existing declaration is the load-bearing
evidence. That object is rebuilt here and still matches.

Generalised: **when a scratch cannot tell two signatures apart, the caller is the
only evidence.** The same class of problem later cost a 33-checksum build on this
branch -- see [`b6faa493`](b6faa493.md), where a callee's parameter *width* was
undetectable in its own bytes and wrong at the call site.

## Byte-width evidence for a still-asm callee

**Fact.** `CanMonsterBeUsedForMission` is still asm, so its prototype is
provisional. Its second parameter is **byte-width**: a caller in
`main_0205D1F4.s` masks with `and r1, r1, #0xff` before the call.

That is a genuine piece of evidence for a provisional declaration -- read off a
caller rather than guessed -- and worth imitating.
