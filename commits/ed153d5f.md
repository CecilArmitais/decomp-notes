## Decompiled

## What changed and why

**Fact.** The eleven handlers decompiled in [`26217737`](26217737.md) and
[`00d4d642`](00d4d642.md) used `(position, seq, track, channel)`. The handlers
**already landed** in `lib/DSE/src/main_02071A98.c` -- the same dispatch family,
reached from the same `SMD_EVENTS_FUN_TABLE` -- use
`(ptr_next_byte, sequence, track, channel)`.

This renames the arm9 ones to match, and follows the existing pointer spelling
for the sub-loop local.

## The verification point

**Parameter names do not affect code generation.** The rebuild was run to
*confirm* that rather than to assume it.

That is the standard this branch tries to hold: a change believed to be
byte-neutral is still built, because "believed byte-neutral" and "verified
byte-neutral" are different claims.

## For a reviewer

The direction of the reconciliation is a judgement: the arm9 names were changed
to match `lib/DSE`, on the grounds that the `lib/DSE` handlers were **already in
the tree** and this branch's were new. If upstream prefers the other spelling,
this commit is trivially reversible and affects no bytes.
