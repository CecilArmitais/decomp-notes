## The inference from the previous commit becomes a fact

**Fact.** `EndTrack` writes `1` to the byte at offset 3 of the second argument,
which is `field_0x0.has_looped` in `struct dse_sequence`.

[`26217737`](26217737.md) could only type that parameter from the dispatcher's
call site, because no handler used it. Now one does.

**Inference, and labelled as such.** That a track reaching the end of its main
loop sets `has_looped` is *consistent*; and no other struct in `dse.h` places a
byte with that meaning at offset 3. That is corroboration, not proof.

## Two findings past the obvious form

Both are general techniques, now in `docs/MATCHING_TIPS.md`.

**1. Byte-width locals insert masks.** `SubLoopEnd`'s index and count locals are
`int`, not `u8`. At byte width the compiler inserts `and rX, rX, #0xff` after
each decrement, which the target does not have.

**2. The early return has to be the fall-through path.** Written as an early
return, the compiler **if-converts** the tail into predicated stores; the target
**branches**, with `bxeq lr`. Inverting the condition -- so the longer body sits
inside the `if` -- produces the branch.

That second one is worth internalising: *which* branch is the fall-through is a
codegen-visible choice, not a style preference.

## Struct reuse

`SubLoopBegin` and `SubLoopEnd` index `track->loop_stack`, the existing
`struct dse_sub_loop[4]` at offset `0x24` with a 12-byte stride -- which is what
the asm's multiply by `0xc` computes.
