## Tooling

**Fact — a bug documented in batch 5 and only half-fixed until now.** The batch
module derives its extern list by splitting the context on `";\n"`. That glues
the **first** declaration of every context to the typedef preamble ahead of it:

```
'#define TRUE 1\n#define FALSE 0\n#define NULL ((void *)0)\n\nextern u8 _022B7310[];'
symbol extracted: NULL
```

The `mentioned` filter then looks for `NULL` in the function body, does not find
it, and discards the element — taking the real declaration with it. The
`a6ce70e5` note recorded this; the *struct* half was fixed then via `ctxsrc`,
the extern half was not. It cost two builds here. `land_from_json.py` now
derives externs from the persisted context by regex and ignores the pre-split
list.

**Fact — a third malformed-block shape.** `asm/main_02008240.s` contains
`sub_02008240`, whose entire body is `ldmia sp!, {r4, r5, r6, pc}` — an
**epilogue** that got its own `.global`, i.e. the tail of the function above it.
It passed the classifier because it *does* end in a return. The classifier now
flags a block that opens by popping callee-saved registers it never pushed.
Four such blocks exist tree-wide. Recorded in `MATCHING_TIPS.md`.

**Fact — a parser bug behind that.** `name: ; 0xADDR` left the address comment
as the block's first "instruction", so any check keyed on `ins[0]` looked at a
comment. Comments are now stripped.
