## The layout is corroborated, not invented

**Fact.** All ten accessors reach a preprocessor-argument block at `+0xC9C` off
a pointer held at `MESSAGE_LOG_INFO + 4`. The block is the **existing**
`struct preprocessor_args` in `include/main_0200C4FC.h`, and its members land
exactly on the offsets the asm uses:

| member | struct offset | asm offset (from 0xC9C) |
|---|---|---|
| `flag_vals[4]` | +0x00 | `0xC9C` |
| `id_vals[5]` | +0x10 | `0xCAC` |
| `number_vals[5]` | +0x24 | `0xCC0` |
| `strings[5]` | +0x38 | `0xCD4` |
| `speaker_id` | +0x4C | `0xCE8` |

Ten independent accessors agreeing with a struct that was already in the tree is
corroboration of that struct, not a new claim about it.

## What is a placeholder

**Fact, and the only invention here.** `MESSAGE_LOG_INFO` itself is a 12-byte
global at `0x023537CC` (its data is `01` followed by eleven zero bytes, and the
next symbol is 12 bytes later). Two of its fields are used: a flag byte at 0 and
a pointer at 4. It is typed `struct unk_023537CC` per the placeholder
convention, named for its address.

**Unknown:** what the pointer points *to*. The accessors reach `+0xC9C`,
`+0xCED` and `+0xCEE` off it, so the pointed-to object is at least ~3.3 KB and
the argument block sits deep inside it. Nothing here models that outer object,
and `field_0x4` is typed `u8 *` so the offsets can be written directly.

## Notes

- **`SetPreprocessorArgsIdVal`** is named without the `MessageLog` prefix its
  nine siblings carry. That is upstream's name from pmdsky-debug, kept verbatim.
- An eleventh candidate, `ov29_0234B010` (the `+0xCEE` byte), also matched at
  score 0 but was left out to keep the batch at ten. It is a one-line change
  whenever wanted.
- **Two tooling frictions**, both already documented and both hit again:
  `extract_function.py` fails on a signature written `struct X *Foo(...)` and
  needs `struct X* Foo(...)`; and a generated header needs `#include "util.h"`
  before it can name `bool8`/`u8`.
