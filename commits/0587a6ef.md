## The open question from `ec25edd9` is closed, and my diagnosis there was wrong

[`ec25edd9`](ec25edd9.md) recorded that `SetLeaderAction`'s provisional
`extern s32 SetActionUseMovePlayer();` could not be replaced by the real header
without failing three modules' checksums, and speculated at length about the
**return type** — whether the function really returns its callee's `r0`.

**That was the wrong suspect.** `SetMonsterActionFields` is already decompiled
and matching as `void` (`src/dungeon_action.c`), so nothing was ever returned
through it. The problem was the **parameters**.

**Fact.** The function was landed as
`(struct action_data *, u8 monster_index, u8 move_index)`. A `u8` parameter
makes every caller truncate its argument. Retail's call site inside
`SetLeaderAction` does not truncate:

```
mov r1, r0                  ; GetTeamMemberIndex result, passed unchanged
mov r2, r4, lsl #0x10
mov r2, r2, asr #0x10       ; sign-extended to 16 bits
bl SetActionUseMovePlayer
```

An unchanged word and a 16-bit sign extension: the parameters are **`s32` and
`s16`**.

## Why it slipped through

**Fact.** The callee stores both parameters with `strb`, which ignores the upper
bits. `u8, u8`, `s32, s16` and `s32, s32` **all score 0** against its own asm —
measured. Nothing in the function being decompiled could distinguish them; only
a *caller* can.

**The general lesson**, and the reason this is worth a note rather than a
one-line fix: a parameter whose only use is a narrowing store is invisible in
the callee. When such a function is landed from its own bytes alone, its
parameter types are a guess dressed as a match — and the guess propagates,
because the next person to touch a caller gets a prototype that forces
truncation the target does not have.

Checking a call site before committing a signature is cheap. This branch has now
been bitten twice in the same family — see also `CanMonsterMoveInDirection` in
[`e8823a88`](e8823a88.md), where a `u16` parameter forced a narrowing at
`SetLeaderAction`'s call site and had to be widened to `s32`.

## Result

**Fact.** With `(struct action_data *, s32, s16)` both functions match, the
provisional extern is deleted, and `SetLeaderAction` includes
`overlay_29_022EBC50.h` instead. One declaration of the symbol now exists in the
tree rather than two contradictory ones.
