## `sub_020564B0` — "is this index the appointed leader's?"

**Fact.** It repeats, instruction for instruction, the roster read that
`GetAppointedLeaderMemberIdx` performs (commit `bf352238`): `active_team` selects
one of the `number_active_team_members_*` fields, and that value indexes
`active_roster_member_idxs`. It compares the result against its argument and
returns false if either the argument or the intermediate is -1.

Since `GetAppointedLeaderMemberIdx` *returns* exactly that value, this is
"is `idx` the appointed leader's member index?".

**This closes both NPC filters** from `47ccc0e1`:

| collector | excludes |
|---|---|
| `GetUnitNpcIds` | the three main characters (`sub_02055410`/`474`/`4D8`) |
| `GetAdventureNpcIds` | the appointed leader (`sub_020564B0`) |

**Matching note**: one restructure, 865 → **0**. The target funnels all three
failure paths to a single trailing `mov r0, #0`; written with early returns they
became predicated `moveq`/`bxeq` at each site. Nesting the guards so everything
falls through to one `return 0` fixed it — the converge-on-one-return technique
already in `MATCHING_TIPS.md`.

## `sub_0201E380` — one palette entry

**Fact.** It passes `&table[(c << 8) + d]` to `Rgb8ToRgb5` along with the caller's
colour pointer, then stores `1` at index `c` of a second, byte-wide table.
`Rgb8ToRgb5` (still asm) reads three bytes as R/G/B and packs them into a
halfword — so `c << 8` is a 256-entry stride.

**Inference.** This reads as "convert one 8-bit RGB colour into palette `c`, slot
`d`, and mark palette `c` dirty". The `1` store is a flag of some kind; that it
means *dirty* is a guess from the shape, not established. Nothing is named on the
strength of it.

**Matching note**: first attempt, score 0. `s16` and `int` for the two index
parameters both match; `s16` was kept because that is how the parameter was
already declared while only the call site was understood.
