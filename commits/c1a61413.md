## What the function does

**Fact** (read off the asm): it copies one `GroundBg` into another — scalars,
`bplHeader`, the `layerSpecs` array, `bmaHeader`, the palettes, the animation
specifications, the `unk4` and `unkC4` arrays, per-layer BPA state and VRAM
pointers, then the `mapRender` array. **Inference**: this is a "clone the
background state" operation; nothing in the bytes names it, so it keeps
`ov11_022ED69C`.

## The match

Progression: 8541 → 105 → **0**.

The last 105 was a single register permutation `(r0 r2)(r1 r5)` across four
values in the BPA loop's preamble, with everything downstream cascading
consistently. **Fact**: ~160 source-shape variants — declaration order, scope,
loop forms, statement order, expression spellings, struct-assignment forms,
pointer-vs-index, hoisting, `volatile` — moved none of it.

What resolved it was reading the aligned diff **with matching rows included**,
which gives the whole live set at that point:

| register | holds |
|---|---|
| `r3` | `k` (the vram slot index) |
| `r4` | `i` (the layer index) |
| `r6` | `&ov11_02320C18[unk0]` |
| `r8`, `fp` | the two loop counters |
| `sl`, `r9` | `dst`, `src` |
| `lr` | `&src->unkC4` |
| `[sp,#0xc]` | `&dst->unkC4`, spilled |

leaving exactly `r0`/`r1`/`r2`/`r5` free. **Fact**: in each swapped pair retail
gives the later-defined, shorter-lived value the low register, and the candidate
gave it to the earlier one. **Inference**: that is a live-range ordering
difference rather than anything about statement shape — which is why shape
variants could not move it.

The fix shortens `unkA`'s live range so it dies into a temp instead of spanning
the combined expression:

```c
/* 105 */
vram = layerVram + (dst->unk2BC.unkA + sp->numTiles) * 16;

/* 0 */
s32 tiles = dst->unk2BC.unkA;

tiles += sp->numTiles;
vram = layerVram + tiles * 16;
```

**Fact**: loop-local, function-scope and renamed spellings are byte-identical, so
the temp's scope carries no information. **Inference**: retail's source probably
accumulated into a variable here; the bytes cannot distinguish that from any
other construct with the same live range, so this is the form that matches, not
recovered intent.

### Two near-misses that were symptoms

Both reached 4-of-7 correct registers and both did it by **deleting instructions
the target has** — hoisting the two `unkC4` base pointers out of the loop, so
`add lr, r9, #0xc4`, `add r0, sl, #0xc4` and its spill vanished from the
preamble. Right registers via wrong structure. Recorded because the scores (841
and 3684) looked like progress against a 105 baseline on the register map alone.

## The tree changes, and the evidence for each

### `BmaHeader::numLayers` / `hasDataLayer` / `hasCollision`: `u16` → `s16`

**Fact.** The scratch matched at 0 with these declared `s16`. Landed against the
tree's `u16`, `OVY_11.sbin` failed by exactly **3 bytes**, 8 apart, each
`0xF4→0xB4` / `0xF6→0xB6` / `0xF8→0xB8`. Bits[7:4] of a load/store-halfword
encode the operation — `0xF` is `ldrsh`, `0xB` is `ldrh`. Retail sign-extends.

**Fact.** This function is the only *reader* of the three fields in the tree.
Every other use is a `strh`, whose encoding is identical either way — which is
why the wrong declaration survived, and why changing it moves no other object.
Confirmed by the full build after the change.

**Suggested for pmdsky-debug**: these three should be signed upstream too. Not
ported here in either direction — flagged as a finding for a human to carry over.

### `MapRender` 0x1C → 0x54

**Fact.** The function strides `0x54` over `GroundBg::mapRender[]` and reaches
fields at `0x1C`, `0x24`, `0x2C`. `0x210 + 2*0x54 == 0x2B8 == `unk2B8``, and the
header's `fillerForNow2[112]` is exactly the `0x38`×2 being consumed, so every
offset after the array is unchanged. `fillerForNow2` was referenced nowhere.

**Fact.** `ground_bg.c` only ever uses `mapRender[0]`, so the stride change moves
no address in already-matching code. **Inference**: the three pointer pairs are
per-layer VRAM/tilemap pointers; nothing names them, so they stay `unk`.

### `GroundBg::unk1FC`: four `u8` → one `s32`

**Fact.** The function assigns and compares it as a word, and the four bytes were
referenced nowhere else in the tree. Same offset, same size.

### Shared declarations moved into `include/ground_bg.h`

`RGB_Array`, the `UnkStruct_2324CBC` family, the three palette helpers,
`ov11_02320C18` and `ov11_02320BF4`/`BE8` were declared inside `src/ground_bg.c`.
The new object needs them and cannot be appended to that file (an asm data object
sits between them in `main.lsf`), so they moved to the header and the `.c` now
includes them.

**Fact.** This is byte-neutral: the binary diff against a clean build showed only
the 3 signedness bytes, so `ground_bg.c` compiled identically. Worth stating
because a plausible worry — that giving `ov11_02320BF4`/`BE8` prior `extern`
declarations would change how MWCC emits those `const` globals — was **wrong**,
and the diff is what settled it.

## Tooling defects hit while landing

1. `extract_function.py` deleted `asm/include/overlay_11_022ECD24.inc` when it
   consumed that `.s`, but `asm/overlay_11_022ECD24_data.s` — a separate object
   in the same address range — still included it. The tool does not know about
   sibling `_data.s` files. Repointed at the surviving `.inc`; verified first
   that the data object's 15 external references all come from `overlay_11.inc`,
   so the range `.inc` contributed nothing to it.
2. The same tool writes `main.lsf` and the new `.s`/`.inc` with **CRLF** into an
   LF repo. Git normalises on commit; a build that copies the working tree does
   not.

Both recorded in `docs/INSERTING_AND_BUILDING.md`.

## Open questions for a reviewer

- **`MapRender`'s trailing `fillerForNow[0x20]`** is unexplored — this function
  copies the struct wholesale and never reads those 32 bytes. Nothing here says
  they are one field or eight.
- **`ov11_022EE9B0` / `ov11_022EE8CC` prototypes** are guesses from two call
  sites (`(MapRender *, PixelPos *)` and `(MapRender *, GroundBg *, s32×4)`).
  They live in `include/overlay_11_022ED69C.h` and should move to the callees'
  own header when those land.
- **The `s32 tiles` temp** is the form that matches, not evidence about retail's
  variable names or scoping — three spellings are byte-identical.
- **Only the US ROM was built.** The function's asm block carries no `JAPAN` or
  `EUROPE` directives, so EU/JP were not expected to differ and were not run.
