## A case where the target does *not* distinguish two spellings

**Fact.** `IsItemWithFlagsInBag` matches an item by id and then by any of a flag
mask. The two conditions can be written as a single `&&` or as nested `if`s;
**both score 0**, so the target does not distinguish them. The `&&` form is used
as the more direct reading.

Worth recording alongside all the cases where spelling *does* matter -- it is
useful to know which choices are free.

## `GetItemIndex` takes a pointer, not an id

**Fact, and this is a real finding about the interface.** The target compares
**the walking cursor against the argument**, not against a field of it. So the
function returns the index of a bag slot **the caller already holds a pointer
to**, and `-1` when the pointer is not in the active inventory.

A reviewer reading the name alone could reasonably expect an id parameter; the
asm says otherwise.

**Fact.** The index is returned through a **16-bit narrowing**, which is why the
return type is `s16` rather than the `s32` the loop counter uses.
