**Fact.** `NewWindowScreenCheck` counts the active windows on each background
before delegating to `NewWindow`, and sets a flag when either screen has none. It
reads `is_active` as a **signed byte at `0xB6`** and `bg_id` at `0x8`, both named
by the layout added in [`30ea1f34`](30ea1f34.md), so the loop reads as what it
does.

## Two codegen requirements, one of them non-obvious

**Fact.** It walks with a **cursor rather than indexing**. Indexing
`WINDOW_LIST[i]` emits an `mla` per iteration; the target advances a pointer by
`0xE0` at the bottom of the loop.

**Fact, and this one is odd.** Its two counters have to be **assigned in the
order sub then main** -- declaration order alone was not enough, and **every
permutation of the four locals left a score between 20 and 95**.

No mechanism was established for why the *assignment* order matters where
declaration order does not. Recorded as an observation, not an explanation.

## The failure worth reading: a 33-checksum cascade with no compile error

**This is the most instructive failure on the branch.**

**Fact.** `SetScreenWindowsColor`'s colour parameter is **`s32`, not `u8`**, and
**that distinction is not visible in its own bytes**: both score 0 against it,
because the store is a `strb` either way.

**It is visible one level up.** `SetBothScreensWindowsColor`, landed matching in
[`643fd53b`](643fd53b.md), passes its argument straight through. A `u8` parameter
makes the compiler **truncate at that call site**, which changes an object that
already matched, changes the size of `main.sbin`, and **shifts every overlay
after it**.

The first build of this batch failed **33 checksums** for that reason, with **no
compile error and nothing wrong in the function being added**.

**Two lessons recorded at the time:**

1. **The scratch is blind to this.** It compiles one function in isolation, so
   any signature choice the callee's bytes do not constrain can still be wrong,
   and only the full build sees it. Third variant of this problem on the branch,
   after [`e6c5c875`](e6c5c875.md) (parameter *count*) and
   [`aade0cdf`](aade0cdf.md) (parameter *type*) -- and the first to manifest as a
   checksum cascade rather than a compile error.
2. **It was diagnosed badly before it was diagnosed well.** Two guesses were made
   first -- a global-declaration conflict, then a heavy include chain -- and both
   made things worse or no better. **Resetting and adding functions back one at a
   time found it in a single build.** "Zero compile errors, all overlays failed"
   means *layout*, not *code*, and should route straight to isolation.

## A declaration conflict avoided

**Fact.** `GetPaletteBaseAddress__020278A8` reads through `_020AFC70`, which
`include/main_02064FFC.h` **already declares as `u8 *`**. It is declared the same
way here rather than being given a second, differently typed declaration.
