## What they do

**Fact.** Both walk the four entries of
`TEAM_MEMBER_TABLE_PTR->active_roster` (stride 0x68 = `sizeof(struct
team_member)`), and for each entry whose flags byte has bit 1 set, take
`member_index` (0x8) and keep it if `IsMonsterIdInNormalRange` accepts it **and**
a filter rejects it. Kept indices are appended to the caller's buffer; the count
is returned.

| | filter — index is dropped when |
|---|---|
| `GetUnitNpcIds` | `sub_02055410` \|\| `sub_02055474` \|\| `sub_020554D8` |
| `GetAdventureNpcIds` | `sub_020564B0` |

**Fact.** `IsMonsterIdInNormalRange` is `0 <= x < 0x22B`. `0x22B` is 555 =
`MAX_GROUND_TEAM_MEMBERS`, so despite its name it is a **member-index** bounds
check, not a species check — consistent with `member_index` being what is passed.
That name is upstream's; nothing was renamed here.

**Inference, and it corroborates the previous commit.** `GetUnitNpcIds`'s filter
is exactly the three predicates from `caf0ff01`, which that note argued are
"is this index main character 1/2/3". So this function collects active roster
members that are *not* main characters — which is what a list of "unit NPCs"
would be. Two functions now independently support that reading.

**Fact worth knowing.** Both tolerate a **null buffer**: the target reserves 8
bytes of stack and redirects the pointer there when the argument is null. That is
why the frame reserves space nothing else uses. Reproduced with a local
`s16 scratch[4]`.

## The flag test is a wart — reviewers should weigh it

The bit test is written `(*(u8 *)m & 2) != 0`, reading the first byte of
`struct team_member` raw.

`common.h` models that byte as `u8 f_is_valid : 1; u8 flags_unk1 : 7;`, and
**no access through those members reproduces the target's single `tst r0, #2`**:

| form | score |
|---|---|
| `m->flags_unk1 & 1` | 210 |
| `m->flags_unk1 & 2` | 205 |
| bit 1 split into its own 1-bit member | 1115 |
| `(*(u8 *)m & 2)` | **0** |

Reading a 7-bit field emits a shift pair to extract it first; only the raw byte
read gives the direct test. So the struct **as currently declared cannot express
this bit test**. The raw read is used rather than changing a struct shared with
the rest of the tree — but that is a judgement call, and a reviewer may prefer
the struct change instead. Flagged rather than quietly chosen.

## One change to already-committed code

Tightening the parameter from `void*` to `s16*` (what both call sites actually
pass, and what the stores write) required `sub_02065050`'s scratch buffers to
change from `u8 unit_buf[8]`/`adv_buf[8]` to `s16 [4]` — the same eight bytes,
and already how `sub_0206549C` declares its own. Rebuilt to confirm
`sub_02065050` stays byte-identical.

## Matching notes

The whole structure was right on the first attempt; both residuals were
mechanical:

1. **The flag test** (above), 305 → 95.
2. **Local declaration order**, 95 → **0**. Every remaining diff was marked as a
   register difference only — same opcodes at the same addresses, with `i`/`m`
   and `idx`/`count` each swapped between register pairs. Hoisting `idx` to
   function scope and ordering the locals `i, m, idx, count` produced the
   target's allocation. Worth remembering: when a diff is *entirely* register
   renaming, reorder the declarations rather than restructuring anything.
