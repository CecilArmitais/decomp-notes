## This is the surviving quarter of a 17-function batch

**Seventeen functions from this cluster reached score 0 on a scratch.** These
four build matching in the tree. **The other thirteen do not** — they fail four
checksums (`main`, `OVY_10`, `OVY_29`, `OVY_31`) **with no compile error**, and
are not in this commit.

The rest of this note is what is known about that failure, recorded so the next
attempt does not repeat the elimination.

## What has been ruled out

**The struct layout is not the cause.** Compile-time assertions against the
*real* headers were added temporarily and **all compiled**, confirming every
offset the scratch context assumed:

| assertion | result |
|---|---|
| `mission_destination` at `0x760` | holds |
| `target_enemy_defeated_message` at `0x1` | holds |
| `target_monster_not_found_flag` at `0x3` | holds |
| `target_enemy_is_defeated` at `0x1B` | holds |
| `fixed_room_id` at `0x16` | holds |
| `enemy_species` at `0xE` | holds |
| `sizeof(enum mission_type) == 1` | holds |
| `sizeof(enum monster_id) == 2` | holds |

That technique is worth reusing: **a block of `typedef char x[cond ? 1 : -1];`
turns a silent checksum mismatch into a compile error that names the wrong
assumption**, for the cost of one build.

**A build of HEAD with no changes is clean**, so the regression is inside the
batch and not pre-existing. **Landing these four alone is clean.** **Adding nine
more — none of which uses a `mission_type` enumerator — reproduces the failure**,
which eliminates the enumerator conversions that were the first suspicion (those
were the one thing changed *after* scratch verification, so they were the
obvious candidate, and they are not it). **No pre-existing declaration** of any
of the seventeen names exists elsewhere in the tree.

## The remaining hypothesis

**Inference, not established.** That `main.sbin` fails *alongside* the overlay
points at something structural rather than at a function body — nothing in this
batch touches main. The two candidates:

- **overlay size**, which would change an overlay-table entry held outside
  `OVY_29`;
- **symbol exports**, since `extract_function.py` rewrites the `.public` list in
  the `.inc` when it splits an overlay `.s`, and the observed diff dropped four
  `.public` names that only the extracted functions referenced.

The `.inc` in question is included by exactly one `.s`, so the *shared-header*
trap from [`0f2e0ea8`](0f2e0ea8.md) is not it.

**Next step:** byte-diff `OVY_29` against a clean build in one container with
`cmp -l`, the technique that located the rodata problem in
[`0f2e0ea8`](0f2e0ea8.md). That turns "four checksums failed" into exact
addresses, and it should have been reached for sooner here.

## What this cost, honestly

Roughly six builds went into elimination, several of them guesses made before
isolating — the same anti-pattern recorded in [`b6faa493`](b6faa493.md). The
assertion block and the HEAD baseline were the two that actually produced
information. **Reach for a decisive test before a plausible fix.**
