## What they do

**Fact.** Each returns a `struct ground_monster *` into
`TEAM_MEMBER_TABLE_PTR->members`, or `NULL` when that entry's `is_valid` bit is
clear:

| function | index |
|---|---|
| `GetHero` | `members[0]` |
| `GetPartner` | `members[1]` |
| `GetMainCharacter1` | `members[2]` in a special episode, else `members[0]` |
| `GetMainCharacter2` | `members[3]` / `members[1]` |
| `GetMainCharacter3` | `members[4]` in a special episode, else `NULL` |

The special-episode branch is `GetGameMode() == GAME_MODE_SPECIAL_EPISODE`
(both pre-existing in the tree). All names used — `ground_monster`,
`team_member_table`, `is_valid`, `members`, and the six function labels — already
existed; this commit introduces none.

## Why this matters for the PR

Decompiling these **proves by construction** what `e1853c6e` could only declare:
the accessors return `struct ground_monster *`, so the `->id` reads that feed the
monster-id output of `sub_0206549C` are reading `ground_monster::id`, the
field `common.h` documents as "0x4: Monster ID". The species typing of the early
`SPECIAL_ACTORS` fields no longer rests on a declared return type — it rests on a
decompiled one.

## Matching notes (three levers, all confirmed to score 0)

1. **`(is_valid & 1) != 0`, not `is_valid & 1`.** The target boolifies to 0/1
   via `tst; movne; moveq` (the `bool8` materialisation); a bare `& 1` emits a
   single `and` and mismatches.
2. **`s16` index, not `int`.** `GetMainCharacter1/2` compute `idx * 0x44`; a
   16-bit index makes MWCC emit `smulbb`, an `int` emits `mul`. (655 → 245.)
3. **Bind `base = members` to a local**, then read `base[idx]` and return
   `base + idx`. This keeps base and offset in separate registers and defers the
   pointer `add` into the valid branch (`addne`) instead of hoisting it
   unconditionally. (245 → 0.) The constant-offset cases (`GetPartner`) did not
   need this — the immediate `add` was already deferred.

Levers 1 and 2 are new to `docs/MATCHING_TIPS.md`.
