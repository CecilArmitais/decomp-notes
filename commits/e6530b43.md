## Matching findings

### A `case` sharing `default`'s body is visible only in the chain's shape

**Fact.** `ov18_0238BFA8`'s target contains

```asm
	cmp   r0, #2
	blt   _default
	beq   _default
```

A range check alone is one branch. `blt` **and** `beq` against the same constant
is a range check *plus* a real `case 2:` whose body is `default`'s. Both labels
resolve to the same address, so the case leaves no other trace.

**Fact, measured**: three cases → flat chain, **630**. Adding `case 2:` above
`default:` → **0**, with MWCC splitting at 8 exactly as the target does. An
`if`/`else` chain → **1850**. A contiguous `case 2:`…`case 6:` run → a jump
table (`addls pc, pc, r0, lsl #2`), **2720**.

### A masked value promotes to `int`

**Fact.** `SetAnimationLiveActor` predicates on `cs` (unsigned) where
`(anim & 0xFF) >= 0x16` emits `ge`. `anim` is `u16`, so the masked value
promotes to `int` and the comparison is signed — the mask's guaranteed range is
irrelevant, the compiler goes by the type. `(u32)` on the masked value: **800 →
0**.

### A store the compiler forwards

**Fact.** `ov11_022E4600`'s target stores through `dst`, then re-reads it
(`mov ip, r0` / `strb r2, [r0], #1` / `ldrsb r2, [ip]`). Every plain spelling
lets MWCC forward the store and test the register it already has. Reading the
second access through a differently-typed pointer reproduces the reload.
**Inference**: this is the same no-CSE mechanism as the `volatile` entry in
`MATCHING_TIPS.md`, reached without `volatile`.

**Fact.** Seven callees were already declared in `src/*.c` and are reused
**verbatim** rather than redeclared: `AdvanceFrame`, `DUNGEON_BUTTON_INPUT`,
`MESSAGE_LOG_INFO`, `GetSimpleMenuResult__0202B870`, `GetLanguage`,
`LoadFileFromRom`, `UnkMapRelatedFunc`. None of the seven is in any header —
the `src/` half of that grep is the half that finds them.

**Fact.** `ov11_0231968C` is the byte string `"NULL"`. It is referenced as an
extern symbol, never written as a literal, per the string-literal entry in
`MATCHING_TIPS.md`.

**Fact.** The per-object check reported the batch clean — size, order, and no
pre-existing change — in **54 seconds**. It also caught, before any build, a
`.c` that used `struct unk_0238C950` without reaching its definition. `hdrcheck`
had passed, because the *header* does not name the struct; only the `.c` does.
**That gap is worth closing**: the header check cannot see a type a `.c` uses.
