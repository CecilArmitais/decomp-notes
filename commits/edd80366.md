## Two helper arguments now have a second data point

**Fact.** Earlier batches saw each of these helpers exactly once, which made
their constant argument look like it might be fixed. It is not:

| helper | earlier call | this batch |
|---|---|---|
| `SetReflectStatus` | `DoMoveCounter` passes `4` | `DoMoveRebound` passes `10` |
| `TryWarp` | `DoMoveWarp` passes `0, 0` | `DoMoveStayAway` passes `1, 0` |

**Inference.** Both third arguments are therefore *selectors* — one helper
implements several move effects, chosen by that value. This is worth recording
because it means the parameter cannot be a flag like `displayMessage`, which is
what the positional analogy used elsewhere in this family would have suggested.
**Nothing here establishes what the values select**, and both parameters are
left with neutral or absent names in the externs.

`DoMovePounce`'s `TryPounce(attacker, defender, 8)` is a single data point again,
and its third parameter is left unnamed.

**Fact.** `DoMoveSlowDown` forwards to `LowerSpeed` with arguments identical to
`DoMoveLowerSpeed1` from [`7c02eea6`](7c02eea6.md) — another pair of distinct
move handlers sharing one implementation, like Block/Shadow Hold.

## Unchanged caveats

The helper prototypes for everything except `LowerSpeed` are written from call
sites; `void` returns are indistinguishable from value-returning helpers here
because the wrappers discard the result.
