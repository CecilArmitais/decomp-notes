## Why these five

**Fact.** This is a cleanup sweep, not a decompilation push. Splitting a `.s`
around a decompiled function leaves the remainder behind, and repeated splits
leave *single-function* asm files. A survey found **112** such files, 53 of them
created by this branch. Each one decompiled deletes an `asm/*.s` and its
`asm/include/*.inc` outright.

These five were chosen as the smallest:

| file removed | function | instructions |
|---|---|---|
| `asm/main_0204FD38.s` | `IncrementNbSteals` | 1 |
| `asm/overlay_29_022EAC78.s` | `ov29_022EAC78` | 1 |
| `asm/overlay_29_0234B010.s` | `ov29_0234B010` | 4 |
| `asm/main_0202BCDC.s` | `IsAdvancedMenuActive` | 8 |
| `asm/main_02030A2C.s` | `SetWindowTitle` | 5 |

**Fact.** 112 single-function asm files → **107** after this commit.

## The weakest claim here

**Inference, and weak.** `IncrementNbSteals` and `ov29_022EAC78` are **empty in
retail** — a bare `bx lr`. Nothing in either function evidences its signature:
no argument register is read, nothing is returned. They are written
`void f(void)`, which is a *guess about arity*, exactly the objection that kept
bare veneers out of earlier batches.

The difference is that here the alternative was leaving a one-instruction file
in the tree forever. A caller that later passes arguments will fail to compile
against the header, which surfaces the error rather than hiding it — but a
reviewer should know the signature rests on nothing.

`IncrementNbSteals` being empty is itself worth noting: the pmdsky-debug name
says it increments a steal counter, and retail does nothing. Either the name is
aspirational or the counter was cut.

## A placeholder refined

**Fact.** `SetWindowTitle` writes a halfword at offset `0x20` of
`struct unk_0202AAA8`, which sat inside the opaque `u8 field_0x9[0x97]`. That
array is split into `field_0x9[0x17]` + `u16 field_0x20` + `field_0x22[0x7E]` —
23 + 2 + 126 = 151 = `0x97`, so the struct's size and every later offset are
unchanged, and nothing in the tree indexed the placeholder.

**Inference.** `field_0x20` is typed `u16` because the store is `strh`. Whether
a "title" is a string id, a message id, or something else is not established;
the parameter is named `title` after the function's own upstream name.

## Remaining work in this direction

**Fact, from the survey.** 107 single-function asm files remain (54 created by
this branch). Of the branch-created ones, 32 are ≤30 instructions. The regions
worst hit are `main_0202A3E4.s` (45 fragments), `overlay_29_02325644.s` (42) and
`overlay_29_0232C524.s` (36), where asm and C files now alternate one-for-one.

`DoMoveReviver` (`asm/overlay_29_0232CE7C.s`, 5 instructions) was deliberately
skipped: it carries a `#ifdef JAPAN` message id (`0xC4B` vs `0xF09`), so it
needs region-conditional C and EU/JP builds rather than the US-only path used
here.
