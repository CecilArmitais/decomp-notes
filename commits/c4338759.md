## Shape of the run

Fifty candidates were located and written **before** anything was compiled into
the tree, all fifty scored in one pass, then the survivors landed together
behind a single build and a single commit. Previous batches interleaved
find/match/build/commit ten at a time.

**Fact: 42 of 50 matched on the first candidate; 8 did not and were dropped.**
Nothing was retried or reshaped — the eight failures share one cause, below.

## The eight that did not land

**Fact.** `DoMoveHealOrder`, `DoMoveScreech`, `DoMoveCharm`, `DoMoveGrowl`,
`DoMoveLowerDefense1`, `DoMoveFakeTears`, `DoMoveFeatherDance` and
`DoMoveMetalSound` all call a five- or six-argument stat helper
(`LowerOffensiveStat`, `LowerDefensiveStat`, `ApplyOffensiveStatMultiplier`,
`ApplyDefensiveStatMultiplier`, `TryIncreaseHp`) that takes a constant on the
**stack**.

Every one differs from its target only in *instruction order*. `DoMoveGrowl`
in full — identical instructions, identical count, different schedule:

```
target                          candidate
ldr r2, [pc]  ; &ATK_STAT_IDX   mov r3, #1
mov r3, #1                      str r3, [sp]
ldr r2, [r2]                    ldr r2, [pc]
str r3, [sp]                    str r3, [sp, #4]
str r3, [sp, #4]                ldr r2, [r2]
bl LowerOffensiveStat           bl LowerOffensiveStat
```

Retail issues the global load first and interleaves the constant stores after
it; the candidate materialises the constant first and sinks the load.

**Falsified, on `DoMoveGrowl` (all still 480):** a named `struct StatIndex`
temporary for the global; literal `1` instead of `TRUE` for the stack
arguments; both together; and a separate declaration-then-assignment of the
temporary. `DoMoveCharm` was tried once before in
[`6174b66b`](6174b66b.md) and behaves identically, so this is one cluster of
eight, not eight problems.

**Untried:** whether the stat globals are read through some other expression in
the original (a macro or accessor), and whether a five-argument call with the
same shape elsewhere in the tree already matches — that would give a worked
example to copy rather than guess against.

## What the 42 rest on

**Fact.** The veneers all set at least one argument register before jumping, so
their arity is evidenced by the bytes rather than assumed — the reason this run
avoided bare `ldr ip, =f; bx ip` veneers, whose arity nothing in the function
establishes.

**Fact.** `GetMinimapData` is declared in a header returning
`struct minimap_display_data *`; the three minimap accessors reach a byte at
`+0xE447`/`+0xE448`, far outside anything that struct models, so they are
written through a `u8 *` extern. That is a modelling choice, not a recovered
type — a reviewer may prefer the struct grow instead.

**Inference.** Every helper prototype not already in a header was written from
its call site; `void` returns where the wrapper discards the result are
unverifiable, as in every batch of this family.
